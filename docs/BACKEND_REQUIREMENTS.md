# GprojectApp 前端所需后台接口与业务逻辑

整理日期：2026-10-04。前端：https://github.com/whath/GprojectApp 。后台：https://github.com/whath/GprojectBack 。

依据当前 Android/Windows Kotlin Compose 前端及本机后台契约副本整理。本文不代表线上已经实现、部署或完成生产数据验收；所有 JSON 行情、金额与日期均为契约示例。

## 1. 交付范围和优先级

| 优先级 | 后台交付 | 当前前端/后台状态 |
| --- | --- | --- |
| P0 | HTTPS/Bearer、各市场交易日、股票和行业目录、历史日线、同日行业成员 | 前端已调用；后台副本已有接口，需要确保覆盖和一致性 |
| P0 | 板块资金、个股主力资金 | 前端已实现请求、解析和图表；后台副本尚未实现 |
| P1 | 龙虎榜、美股配置观察列表 | 已调用，需要真实采集与口径验收 |
| P1 | 美国、日本、韩国、原油、黄金的重点事件 | 前端可选契约已完成；后台副本未实现 |
| P2 | 日韩/A股指数、黄金/原油行情、分钟线、估值指标、连板梯队 | 当前为待接入区域，路由未在前端实现，需要双端开发 |
| P3 | 国内大模型舆情、事件和财报分析 | 只有配置入口及代码扩展点，没有模型请求，需要另行接入 |

当前指标和筛选在客户端计算；观察池、置顶、板块关注与已读本地保存。后台现阶段不必实现账户同步、自动交易、关闭 App 后推送或模型分析；这些功能均不能视为已经上线。

## 2. 通用协议与数据约束

- HTTPS 基地址必须具备有效证书，手机和 PC 均可访问。所有以下行情请求携带 `Authorization: Bearer <用户令牌>`；客户端不跟随自动重定向、不接受明文 HTTP，不应返回登录网页。
- 成功响应为 JSON object，列表使用 `items`，建议 `Content-Type: application/json`。数值必须有限，缺失值使用 null，不返回 NaN/Infinity。
- 401 表示令牌失效；其他非2xx表示请求失败。可选资金/事件端点404或501表示尚未接入。不能用200空列表掩盖认证或采集失败。
- 客户端主要按HTTP状态处理错误，没有通用业务错误码解析。后台可以附加 `code/message/request_id`，但不要仅在200中编码错误。
- 连接超时10秒，请求超时20秒。API宜读取已采集快照，避免请求中同步抓取全市场数据；不要要求客户端轮询异步任务替代现有响应。
- A股ID=`CN.stock.六位代码`，如 `CN.stock.688981`；美股=`US.stock.NVDA`；同花顺行业如 `CN.industry.THS_881121`。A股目录ID和symbol必须完全对应。
- `trade_date` 为该市场日期 `YYYY-MM-DD`；时间戳使用带时区ISO8601，如 `2026-09-30T09:00:00Z`。CN/US分别使用交易所日历和收盘状态，不能直接取设备今天或把中国日期套给美股。
- 历史数组日期升序、唯一；限量请求先取end以内最近N条，再升序输出。日线统一不复权，同一序列不混来源、复权方式或成交量单位。
- 涨幅为百分数数值：1.2表示1.2%，不是0.012。资金为人民币元；成交量明确 `share`（股）或 `lot_100_shares`（百股手）；成交额不得当资金流。
- 区分缺失、停牌、非交易日与真实0；缺口不填零、不虚构交易日。采集状态、来源和更新日期必须可信。
- 真实接口失败不允许回退模拟行情；演示数据仅存在于独立演示模式。

## 3. 当前已调用的基础接口

### 3.1 标的与行业目录

`GET /v1/instruments?market=CN&kind=stock&limit=500&offset=0`

行业索引同路径使用 `kind=industry`，只取 `CN.industry.THS_` 行业，不能混概念板块或其他供应商分类。

```json
{"total":1,"items":[{"id":"CN.stock.688981","symbol":"688981","name":"示例股票","market":"CN","kind":"stock","currency":"CNY"}]}
```

- total为过滤后全量记录数，不是本页数量。limit须支持500；offset从0开始，稳定排序（例如ID升序）。
- 一次分页总数不变、ID不重复、不能提前空页或静默截断，否则客户端拒绝将扫描标记完整。
- 后台负责全上市目录、退市/上市更新与历史覆盖。扫描完已有目录不等于覆盖全部交易所股票，需另外提供覆盖审计。

### 3.2 股票及行业日线

`GET /v1/bars/{instrument_id}?end=2026-09-30&limit=2000`

调用窗口：个股详情2000根；筛选每股250根；观察池股票/行业走势和成分行情40根。支持CN股票、US股票及行业ID。

```json
{
 "instrument":{"id":"CN.stock.688981","symbol":"688981","currency":"CNY"},
 "adjustment":"none",
 "items":[{"trade_date":"2026-09-30","open":10.0,"high":10.5,"low":9.8,"close":10.2,
 "volume":123456,"volume_unit":"lot_100_shares","amount":125000000,"change_pct":1.2,"source":"provider/daily"}]
}
```

- end含当日；日期尚未确认时客户端可能省略end，后台返回合理最新历史，不混入未来行情。
- OHLC为正有限数，high≥max(open,close)，low≤min(open,close)；source必填，顶层adjustment必须为none。
- volume/amount非负，可null。图表允许缺成交量，技术筛选要求计算窗口中量完整且同源同单位，未知单位不能参与量比。
- change_pct使用供应商单日口径，缺上一市场交易日时不能拿更早日变化冒充单日涨幅；保留公司行动影响说明。
- instrument.currency真实准确，美股不能错误返回CNY。

### 3.3 行业排行与中国目标交易日

`GET /v1/cn/rankings?limit=50&classification_source=ths`

监控用limit=1校准目标日；扫描也用limit=1，但当前扫描请求未显式指定classification_source，因此各分类的CN目标日必须一致。

```json
{"trade_date":"2026-09-30","classification_source":"ths","scope":"collected_instruments_only",
 "items":[{"id":"CN.industry.THS_881121","name":"示例行业","price_change_pct":1.2}]}
```

- 默认kind=industry，记录属于返回trade_date，不能静默回退旧行情却仍声称目标日。
- 后台现有price_change_pct为同源不复权收盘相对上一市场交易日收盘的变化，不是交易所除权参考价涨幅。上一交易日缺数时不找更早价格补算。
- 可附加previous_session、task_coverage、return_basis。前端目前最多加载50个行业再排序，不是全市场涨跌家数接口。

### 3.4 板块同日成员

`GET /v1/cn/boards/{board_id}/members?observed_date=2026-09-30&limit=500&offset=0`

```json
{"trade_date":"2026-09-30","items":[{"symbol":"688981","name":"示例股票"}],"task_status":[{"status":"complete"}]}
```

- trade_date必须等于observed_date；禁止用今日成员冒充历史日成员、用其他分类代替同花顺。
- 归属索引按500条分页直到不足500条，整页之后需允许再读空页，分页成员代码不重复。
- task_status非空且每项status=complete才视为完整；状态缺失、失败或初始空页会标记未完整确认，不得虚报complete。
- 观察池按六位股票代码反向关联，可能关联多个已核验行业。板块详情仅请求前10项，作为明确标注的成分样本，不是全板块排名。

### 3.5 龙虎榜

`GET /v1/cn/lhb?limit=50`

```json
{"trade_date":"2026-09-30","items":[{"name":"示例股票","symbol":"688981","net_amount":12000000,"reason":"示例上榜原因"}],"task_status":[{"status":"complete"}]}
```

- 当前不传trade_date，后台决定CN披露目标日并返回；net_amount单位人民币元。
- 保留逐条原因、单日/多日统计区间和来源，不跨原因或周期合并净买额；净买额不是全市场主力净流入。
- 空items只表示没有已核验存储记录，不能证明没有披露。建议扩展披露ID、周期起止、发布时间等，但当前UI未完全消费这些字段。
- “查看全部”目前表示已加载最多50条，前端尚无龙虎榜分页；超过50条和席位详情需要后续前端开发。

### 3.6 美股配置观察列表

`GET /v1/us/ai`

```json
{"items":[{"symbol":"NVDA","group":"示例分组","close":100.0,"change_1d_pct":1.2,"trade_date":"2026-09-30","source":"provider/us-daily"}]}
```

各项提供对应美股交易日；点击后以该日为end读取 `US.stock.{symbol}` 日线。group当前作为列表名称，空时回退symbol。路径中的ai表示后台配置的美股观察列表，不是大模型分析，也不是全美股筛选。

## 4. 客户端已支持、后台待补齐的接口

### 4.1 板块资金

`GET /v1/cn/boards/{board_id}/flows?limit=20&classification_source=ths`

```json
{
 "board_id":"CN.industry.THS_881121","classification_source":"ths","currency":"CNY","unit":"yuan",
 "scope":"main","source":"provider/main-order-flow","updated_at":"2026-09-30T09:00:00Z",
 "trade_dates":["2026-09-29","2026-09-30"],
 "items":[{"trade_date":"2026-09-29","inflow":150000000,"outflow":120000000,"net":30000000},
 {"trade_date":"2026-09-30","inflow":null,"outflow":null,"net":-10000000}]
}
```

- trade_dates为应有最近至多20个交易日的升序唯一日历，不能从已有items反推；缺采集的交易日仍要保留。
- scope为main或all，CNY/yuan、来源、板块ID和分类一致。主力分类由供应商定义，并保持整段口径一致。
- net必填可正负；inflow/outflow缺失可null，有值非负；两者齐全要求inflow−outflow≈net，容差max(1元,|net|×0.01%)。
- 前端按5/10/20日计算，仅完整窗口且无接口错误给出累计。正净额和负净额绝对值分别求和，不是买卖总额。
- 连续至少3个交易日净流出提示关注；缺日、请求失败、末日不等于目标日不作为当前提醒。

### 4.2 个股主力资金

`GET /v1/cn/stocks/{instrument_id}/flows?end=2026-09-30&limit=2000`

```json
{
 "instrument_id":"CN.stock.688981","currency":"CNY","unit":"yuan","scope":"main",
 "source":"provider/main-order-flow","updated_at":"2026-09-30T09:00:00Z",
 "items":[{"trade_date":"2026-09-30","inflow":null,"outflow":null,"net":-12500000}]
}
```

- 仅A股，ID严格对应请求，只接受main主力口径；禁止以板块资金、总成交额或全市场资金替代。
- 最多2000条，日期不晚于end；重复、非有限数、单位/来源混杂、净额与总额矛盾拒绝整段。金额约束同板块资金。
- 日图按日期匹配，周/月必须覆盖该根所有已观测日线才相加，任一天缺数则未知，不补零。首尾周期可能不完整。
- 资金与日线并发读取；资金失败仅影响资金区域，不清空成功K线；离开详情取消未完成请求。
- source须可追溯，不同供应商的大单/超大单/主力定义不能默认为一致；当前美股不调用此资金接口。

### 4.3 市场重点事件

`GET /v1/events?limit=100`

```json
{
 "updated_at":"2026-10-02T01:00:00Z",
 "items":[{"id":"stable-event-id","title":"示例事件","summary":"可核查摘要",
 "markets":["US","GOLD"],"importance":"high","kind":"scheduled",
 "occurs_at":"2026-10-03T06:00:00Z","published_at":"2026-10-02T00:00:00Z",
 "expires_at":"2026-10-04T00:00:00Z","updated_at":"2026-10-02T01:00:00Z",
 "source":"发布机构","url":"https://example.org/event"}]
}
```

- markets可多选US/JP/KR/OIL/GOLD，由后台分配，不靠客户端猜标题；importance=high/normal，kind=scheduled/news。
- 所有时间带时区，expires_at晚于published_at。只有已发布且未过期事件展示，优先high再按发生时间排列。
- id稳定，修订时updated_at更新；同ID取最新版本。已读键=id+updated_at，跨市场共享。取消/延期需更新版本、摘要与有效期。
- feed超过24小时未更新或请求失败时前端标记历史并抑制新事件状态。不能用新feed时间掩盖长期未核验内容。
- 来源名称与HTTPS原文链接必填，后台负责事实出处、摘要准确性、去重和新闻授权。空事件不代表没有风险。

## 5. 后台业务处理顺序

1. 更新标的目录、上市/退市状态和市场日历，分别确定CN/US目标日，处理节假日、夏令时、停牌和IPO历史不足。
2. 采集同源不复权OHLC与成交信息；校验价格、日期、单位和唯一键 `(instrument_id, trade_date, source, adjustment)`。
3. 按日期保存同花顺行业成员；提供稳定分页快照，完整采集后才标记complete。
4. 独立采集板块与个股资金，统一人民币元并保存供应商分类；禁止从价格/成交量估算“真实资金”。
5. 保存龙虎榜逐条披露和统计周期；采集全球事件并维护市场关联、原文、版本与有效期。
6. API读取一致快照，各数据集独立失败；保存采集状态、最后成功日期、失败原因和重试次数，不能某个源失败阻断全部行情。
7. 安排缺口重采集、历史回补与公司行动更新，保留来源/分类版本变更记录，避免一次响应混入新旧版本。

负载特点：目录500条分页，全量扫描每股250根、每批4请求；观察池遍历行业成员建立反向索引，再读取股票及行业40根历史。完整同日索引会缓存，不完整索引和手动刷新会重试。建议缓存目录/同日成分/历史查询，提供数据库索引与限流；当前不支持用任务ID、SSE或批量异步扫描协议直接替换现有请求。

## 6. 客户端负责的业务，不应重复假设后台已经实现

- 标准日MA为3/5/8/12/15/20/125，包含当前收盘；MA125至少125根。默认趋势MA20/MA125，比较五根前均线需130根。
- MACD(12,26,9)：EMA以首N项SMA初始化；DIF=EMA12−EMA26，DEA=EMA9(DIF)，柱=2×(DIF−DEA)，第34根出现完整结果。不同历史长度或种子可造成与其他平台差异。
- RSI14用Wilder平滑；量比=当前量/此前20根均量；突破排除当前柱。顶部、下跌趋势、回调横盘、放量突破、底部反转由客户端计算，不要求后台返回指标。
- 周线按周一开始的自然周，月线按自然月聚合；对应MA/MACD随图表周期变化，但详情风险分析仍是日线。缺日不补造。
- 全量筛选由用户主动触发，输入不是观察池；不会每五分钟自动扫描整个市场，再次扫描不自动增删观察池或买卖。
- 应用内监控五分钟更新；Android退后台暂停，前台恢复，Windows运行时更新；无关闭应用后的推送。
- 观察池加入/移出/撤销/置顶、关注、已读和模型配置本地保存，不跨设备同步；行情token和模型key只在会话内存。

## 7. 仍需双端开发的功能与字段建议

下表不是已接入的路由。仅后台新增接口，不会让当前UI自动变为真实数据。

| 功能 | 后台应提供的信息及业务规则 | 前端待做 |
| --- | --- | --- |
| 日韩/A股指数 | 指数ID、交易所/时区/日历、点位/前收盘/涨幅、历史、单位、时效 | 新请求/模型，不能用ETF价格替代指数 |
| 黄金/原油 | 合约ID、交易所、币种、报价单位、到期/换月、主连拼接、历史 | 区分主连与单合约，接入走势和时效 |
| 分钟行情 | 带时区时间戳、交易时段、价格/成交量/额、暂停/竞价/延迟 | 接入分时，处理交易时段与缺口 |
| 换手率/市值/PE | as_of、币种、股本和总/流通口径、TTM/静态PE、负盈利、公司行动 | 数值与口径展示，不以0表示缺失 |
| 连板梯队 | 交易所涨跌停规则、ST/板块/IPO特殊规则、收盘封板、断板/停牌、连续有效日 | 替换占位，提供可核查明细 |
| 更完整龙虎榜 | 分页、披露ID、周期起止、营业部/机构席位 | 超过50条分页和席位详情 |
| 归属性能优化 | 按股票及日期批量返回行业/概念、分类版本与完整性 | 替换目前的全行业遍历 |
| 国内模型分析 | 供应商适配、原文、来源/版本、预算/超时、结构化结果和引用 | 分析触发、HTTP适配器与结果页面 |

模型目前只有服务标签、HTTPS地址、模型/部署ID和 `SENTIMENT / IMPORTANT_EVENT / EARNINGS` 扩展类型，无HTTP请求。若采用后端网关，建议后台托管供应商密钥，分离行情token和模型凭证；明确发送内容范围、成本控制、原文引用及事实/模型判断边界。尚未固定后台模型路由，`/v1/us/ai` 不是模型分析接口。

## 8. 联调验收清单

- [ ] 手机/PC访问同一HTTPS，正确与失效token、超时、断网、恢复、非2xx可区分。
- [ ] 501条以上目录分页，total稳定、无重复和截断，ID与六位代码一致。
- [ ] 250/2000条历史升序与end正确；124/125根MA、129/130根趋势、33/34根MACD边界正确。
- [ ] 节假日、跨年、美国夏令时、CN/US不同日、停牌、IPO短历史不串日期。
- [ ] 资金元/万元/亿元转换、同日错股、来源、净額关系、重复/未来日期被校验；缺失与0不同。
- [ ] 板块日历保留缺采集交易日，5/10/20日累计和连续净流出正确，历史或失败数据不触发当前提醒。
- [ ] 同日行业成员和任务complete真实，未完整索引不声称全覆盖。
- [ ] 龙虎榜多原因/多周期不错误合并，披露日期与当前K线分别显示。
- [ ] 事件多市场、重复ID修订、发布时间、过期/取消/延期、24小时旧源均正确。
