# 应用内监控与数据接口约定

客户端已实现资金跟踪、事件提醒、刷新与错误处理。现有 GprojectBack 尚未提供以下两个端点，生产数据源和服务端采集仍待接入；文中 JSON 是接口测试样例，不是行情事实。

## 运行方式

应用内每 5 分钟刷新当前板块、关注板块和事件，同时通过行业排行 `limit=1` 校准服务目标交易日，防止跨日后沿用打开应用时的旧日期；校准失败时暂停资金提醒。Android 离开前台暂停，回到前台刷新；Windows 程序运行时更新。支持暂停自动更新与手动更新，无系统通知或关闭应用后的推送。最多关注 12 个板块，支持近 5／10／20 个交易日。

真实模式在本地保存监控开关、窗口、关注板块和已读事件版本；Android 使用私有 SharedPreferences，Windows 使用用户目录 `.gproject/monitor.json`。不保存令牌。演示操作不覆盖真实偏好。

两个端点都使用用户配置的 HTTPS API 根地址与同一 Bearer 认证，不直接向第三方新闻网站发送令牌。HTTP 404/501 显示“接口待接入”；401 显示认证错误；失败可保留历史内容，但标明错误并抑制资金累计值、资金告警与新事件标识。真实失败不回退模拟数据。

## 板块日资金

`GET /v1/cn/boards/{board_id}/flows?limit=20&classification_source=ths`

```json
{
  "board_id": "CN.industry.THS_881121",
  "classification_source": "ths",
  "currency": "CNY",
  "unit": "yuan",
  "scope": "main",
  "source": "供应方及统计口径标识",
  "updated_at": "2026-09-30T09:00:00Z",
  "trade_dates": ["2026-09-29", "2026-09-30"],
  "items": [
    {"trade_date": "2026-09-29", "inflow": 150000000, "outflow": 120000000, "net": 30000000},
    {"trade_date": "2026-09-30", "inflow": null, "outflow": null, "net": -10000000}
  ]
}
```

- `trade_dates` 必须是应有的最近至多 20 个交易日（升序且唯一），**不得从有数据的 items 反推日历**。节假日不在日历中，缺采集的交易日仍须保留，以使客户端识别缺数。
- `scope` 为 `main`（主力）或 `all`（全口径），必须展示来源。同花顺分类的板块标识不可直接映射到其他供应商行业；统计口径和成员范围需由后端保证一致。不得用成交额代替资金流。
- `net` 必填，为流入减流出的有符号金额；流入／流出总额可缺失，客户端不反推。提供两者时要求非负且与净额一致，容差为 1 元与净额绝对值的 0.01% 的较大者。
- 所有数值必须有限。币种人民币，金额为元；不要将万元或亿元未经转换传入。日期异常、分类不符、重复日期、净额矛盾会拒绝整批。
- 累计净额只有窗口交易日与记录全部齐全时才计算。净流入日合计与净流出日合计是正／负净额分别求和，不是买卖总额。逐日表单独展示供应商的流入／流出总额。
- 连续至少 3 个已观测交易日净流出产生应用内提醒；缺日或请求失败中断连续性。数据末日不等于行情服务目标交易日时显示历史快照并抑制当前提醒。

## 市场重点事件

`GET /v1/events?limit=100`

```json
{
  "updated_at": "2026-10-02T01:00:00Z",
  "items": [{
    "id": "provider-stable-event-id",
    "title": "测试事件标题",
    "summary": "测试摘要：说明事件及关联市场，不推断必然涨跌。",
    "markets": ["US", "GOLD"],
    "importance": "high",
    "kind": "scheduled",
    "occurs_at": "2026-10-03T06:00:00Z",
    "published_at": "2026-10-02T00:00:00Z",
    "expires_at": "2026-10-04T00:00:00Z",
    "updated_at": "2026-10-02T01:00:00Z",
    "source": "发布机构",
    "url": "https://example.org/event"
  }]
}
```

- `markets` 可多选：`US` 美股、`JP` 日本、`KR` 韩国、`OIL` 原油、`GOLD` 黄金。由服务端基于事件内容分配，客户端不凭标题猜测市场。同一事件可在多个市场显示，共享已读状态。
- `importance` 为 `high`/`normal`，`kind` 为 `scheduled`（日程）/`news`（新闻）。所有时间须为 ISO 8601 带时区的时刻；客户端统一显示北京时间。
- 来源名称和 HTTPS 原文链接必填。`published_at` 决定是否可见，`expires_at` 决定是否过期；失效时间必须晚于发布时间。`occurs_at` 是预计或实际发生时间，避免混同报道发布时间。
- 相同 `id` 取 `updated_at` 最新版本；已读标识为 `id + updated_at`，重要更新可再次提示。取消或修订事件时需更新版本、摘要及有效期。过期或尚未发布的事件不显示。
- 事件列表超过 24 小时未更新显示过期提示，抑制新事件标识。有效空列表显示暂无事件，不能把接口失败解释成没有事件。
- 供应方须负责可信出处、更新、去重、授权与摘要准确性。当前演示条目只展示交互，官方链接供查阅，不将其模拟时间当作真实会议或数据发布时间。

## 接入验收

先在后端实现以上端点并提供有效来源，再在设置中连接服务。核对节假日、缺交易日、口径转换、事件更新/取消、认证过期、网络中断和恢复。客户端 MockEngine 合约测试不等于生产联调。
