# 全量扫描、个股观察池与模型扩展

## 使用流程

信号雷达选择组合或自定义参数 → 扫描全量 A 股目录 → 在符合条件的结果上点击“加入观察池” → 进入“观察池”管理。加入、移出和置顶均为手动操作；条件变化、再次扫描或未再次命中都不会自动移出。

观察池按置顶优先、加入时间倒序排列。真实模式本地保存标的身份、加入时间与置顶状态。Windows 保存于用户目录 `.gproject/workspace.json`；Android 使用私有 SharedPreferences `workspace`。行情与板块匹配信息不持久化，连接服务后重新加载；演示观察池与真实设置隔离。

## 扫描与范围

- `/v1/instruments?market=CN&kind=stock&limit=500&offset=...` 读取至服务端 `total`。总数变化、重复标识、提前空页会使扫描失败，不把截断目录标为完成。
- 按冻结的本轮筛选参数读取每只股票 250 根日线，分批最多 4 请求并行；401 终止本轮，普通行情缺失计入排除数。扫描进度与有效结果按批更新，停止后保留已处理范围的结果，明确未完成状态。
- 重新扫描和切换连接取消旧任务，通过任务代次防止旧结果覆盖新状态。观察池不是扫描输入，只是手动跟踪集合。
- 当前默认为 A 股，不混用美股时区、交易日和行业分类。客户端遍历全部已有目录不代表后端已采集全部上市公司，生产验收须核对目录覆盖。

## 所属板块与资金

- 分页读取同花顺行业目录与目标交易日的 `/v1/cn/boards/{id}/members`，以精确股票代码建立反向匹配。同一股票可对应多个已核验行业记录，不按名称猜测，不替换成其他供应商分类，也不把行业与概念混合。
- 成分分页每页 500 条直至不足一页，要求日期一致、股票代码有效且不重复；失败或不完整快照会提示覆盖状态。完整索引在本次连接同一目标日期内复用；不完整索引下次自动更新时重试，手动刷新会清除缓存。
- 读取每只观察股和去重后的关联板块近 40 根收盘数据，展示日期、来源、走势与涨跌幅；旧快照明确标识。
- 关联板块复用资金流接口、统计口径及 5/10/20 日窗口。缺日不计算完整累计值，缺失总流入/总流出不反推；来源未接入明确显示待接入。完整资金约定见 [INTELLIGENCE_API.md](INTELLIGENCE_API.md)。
- 自动刷新与现有应用内监控共享开关及五分钟周期；Android 离开前台暂停。未开启系统推送。全量筛选需要主动发起，监控不会每五分钟重新扫描整个市场。

## 国内模型预留入口

观察池页尾“监控与数据”或连接设置中进入“国内大模型 API”。可保存服务标记、HTTPS API 根地址与模型/部署 ID，预留面向兼容 Chat Completions 接口的配置。通义、DeepSeek、智谱、豆包只是服务标签，不含固定模型名/接口地址，也不保证所有原生协议通用；需按实际供应商文档填写。

API Key 只在 ViewModel 内存中保留，输入框遮挡，不进入偏好文件、行情接口请求或日志。换服务或根地址会清除旧密钥；同服务留空可保留本次会话密钥，也可主动清除。HTTPS 地址拒绝用户名、密码、查询参数与 fragment，避免把凭证嵌入可保存地址。

当前只保存配置并定义扩展接口，**没有模型 HTTP 请求实现，也没有已启用的舆情/事件/财报分析**。因此保存配置不代表验证了连通性或模型权限，不会自动传输观察池、新闻或财报内容。

扩展点位于 `Workspace.kt`：

- `AnalysisKind`：`SENTIMENT`、`IMPORTANT_EVENT`、`EARNINGS`。
- `AnalysisRequest`：分析类型、标的 ID、待分析文本、来源链接。
- `AnalysisResult`：摘要、来源链接、生成时间。
- `MarketAnalysisProvider`：可替换的异步分析提供者接口。

后续实现独立模型 HTTP 客户端/后端网关，使用独立凭证，加入请求预算、超时与供应商协议适配。只有用户启用具体分析后才把所选原文送入分析接口；结果需保留原始出处，并与行情事实区分。
